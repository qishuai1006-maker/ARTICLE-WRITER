# ContentFleet v3.1 复盘报告 · 2026-04-15

## 一、问题总结（致命失误）

### 问题1：T3初稿漏掉QD-Mini LED技术路线（P0）

**现象**：头条/知乎/smzdm/小红书四平台初稿只写了「RGB-Mini LED vs OLED」两条路线，完全没有QD-Mini LED（三星Neo QLED）的身影。但配图里却有三路线内容，正文配图严重不一致。

**根因**：
- 调研资料里QD-Mini LED数据充足（三星85QNX9D/TCL 98T7L Ultra等）
- 调研资料标题和内容明确写了「三条路线」但T3写手只抓了两条
- CEO审批T1选题池时未强制核查「三条路线是否完整写入T3提纲」

**影响**：返工T6四平台终稿 + 重新生成3张配图，浪费约2小时

**复盘规则新增**：
> **T1选题池审批时，CEO必须确认文章主轴的技术路线数量，并在T3提纲里写死**
> T3全栈写手执行前，CEO审批提纲中必须明确标注技术路线的完整数量和名称

### 问题2：配图与正文不同步（P0）

**现象**：
- T5_01封面图：只有RGB-Mini LED vs OLED
- T5_04优缺点图：只有RGB-Mini LED vs OLED
- T5_05人群选购图：只有RGB-Mini LED vs OLED

配图生成时未严格对照文章实际写了几条路线。

**根因**：
- T5提示词包由视觉分发师独立编写，未与T3终稿的内容进行交叉验证
- T5与T3是并行执行，视觉分发师不知道T3最终写了几条路线
- T5提示词包里的封面图/优缺点图提示词只写了「OLED vs Mini LED」两条路线

**复盘规则新增**：
> **T5执行前必须读取T3终稿**，确认文章实际技术路线数量后再生成提示词
> T5提示词包完成后，视觉分发师必须对照T3终稿逐图核查：图内技术路线数量 ≥ 文章内技术路线数量
> **T5文件存在性验证时，同步做内容一致性抽查**（抽检至少1张图是否与文章匹配）

## 三、流程漏洞分析

### 3.1 T4合规审查失效

合规风控师执行了「Humanizer + 四平台格式核查」，但**没有核查文章技术路线的完整性与配图的路线数量是否一致**。这属于「T4质量门禁覆盖范围不足」。

**新增T4核查项**：
```
[ ] 文章与配图路线一致性：配图数量 ≥ 文章技术路线数量
```

### 3.2 T5与T3并行导致信息不对称

T5与T2/T3并行是v3.1的优化，但并行意味着视觉分发师在T5执行时不知道T3最终产出。如果T3大幅偏离提纲，T5提示词就失效。

**复盘决策**：
> T5提示词包生成后，追加一步：「视觉分发师等待T3终稿确认，再正式生成配图」
> 具体做法：T5提示词准备好 → 等T3完成 → 视觉分发师快速通读T3确认路线 → 再正式生成

## 四、T3写手为什么会漏掉QD-Mini LED？

分析原因：
1. 调研资料里RGB-Mini LED数据最强（海信5300 nits、9999元性价比）
2. QD-Mini LED数据相对分散（三星、索尼各有千秋）
3. 写手优先突出RGB-Mini LED优势，把QD-Mini LED归类为「介于两者之间」一笔带过
4. 但实际上三星QNX9D（11925元/85寸）是重要选购节点，不能省略

**复盘规则新增**：
> **T3质量门禁新增：技术路线完整性核查**
> ```
> [ ] 文章是否覆盖了所有预设技术路线？（数量必须与T1审批一致）
> [ ] 每条技术路线是否有：代表机型 ≥ 1款、核心参数表含该路线、优缺点各 ≥ 2条
> ```

## 五、团队协作问题

### 5.1 选题情报官 → 全栈写手 的信息传递断层

T1选题池确认了「三条路线」，但这条信息在T3里丢失。

**根因**：T1和T3之间没有结构化的「交接清单」，T3写手是通读T1+T2后自己理解，容易主观取舍。

**复盘规则新增**：
> T2素材包交付时，必须包含一个**「文章骨架清单」**：
> ```
> ## 文章骨架（CEO审批后锁定）
> - 技术路线数量：3条
> - 路线名称：RGB-Mini LED / QD-Mini LED / QD-OLED
> - 每条路线代表机型：海信E8S / 三星85QNX9D / 索尼A95L
> - 必须覆盖的对比维度：亮度/黑场/游戏/色彩/寿命
> ```
> T3写手必须严格照此执行，不得删减路线

### 5.2 团队关闭延迟

全流程跑完后，有4个Agent未主动响应关闭请求，需要TeamLead反复发送shutdown_request。

**复盘规则**：项目归档完成后，TeamLead广播解散消息，5个Agent必须在5分钟内响应关闭。超时由TeamLead强制终止。
