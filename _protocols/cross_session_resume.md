# 跨会话恢复指南 v1.0

> **目的**：上次会话挂了，5 分钟内恢复现场继续干
> **最后更新**：2026-06-11

## 场景 1：T3 写到一半，对话框关了 / 报错 / 网络断了

### 5 分钟恢复步骤

```bash
# 1. 看 test_run/ 目录下最新文件
ls -lt test_run/选题_*.md | head -5

# 2. 找最新的那篇，打开看进度
cat test_run/选题_2026-06-11_冰箱_法式门vs对开门.md

# 3. 看末尾的进度标记（每完成一个 T 都会追加）
```

### 恢复对话开头话术

```
我之前在 T3 写到一半会话挂了。
请你读取 test_run/选题_2026-06-11_冰箱_法式门vs对开门.md，
检查当前进度（T1/T1.5/T2 已完成，T3 未完成），
然后接着 T3 写正文。
参考 prompts/04-写作/写作_骨架填空模板.md 的规则。
记住：对话里不许重复 Prompt 规则，只引用文件路径。
```

### 进度标记格式

每篇 `选题_*.md` 文件末尾会自动追加：

```markdown
## 进度
- [x] T1 选题（5 角度 + 选定）  ← 2026-06-11 09:30
- [x] T1.5 骨架选型 + 标题      ← 2026-06-11 09:45
- [x] T2 三层深度               ← 2026-06-11 10:15
- [ ] T3 写作（进行中）         ← 2026-06-11 10:30
- [ ] T4 自检
```

## 场景 2：跨天继续（比如昨天 T2 跑完，今天跑 T3）

### 5 分钟恢复步骤

```bash
# 1. 看今天要接哪一篇
ls -lt test_run/选题_*.md | head -10

# 2. 找进度卡在 T2 或 T3 的
grep -l "T3 写作（进行中）" test_run/选题_*.md

# 3. 或者看 _handoff/ 目录找最新 YAML
ls -lt test_run/_handoff/*.yaml
```

### 恢复对话开头

```
昨天的 T2 跑完了，今天接着跑 T3。
读取 test_run/_handoff/[文章ID]_T2.yaml 看完整决策，
读取 test_run/选题_2026-06-11_冰箱_法式门vs对开门.md 看进度，
按 prompts/04-写作/写作_骨架填空模板.md 写正文。
```

## 场景 3：多篇并行（一天 3-5 篇）

### 推荐组织方式

```
test_run/
├── 选题_2026-06-11_冰箱_A_法式门.md      ← 第 1 篇
├── 选题_2026-06-11_冰箱_B_对开门.md      ← 第 2 篇
├── 选题_2026-06-11_空调_挂机横评.md      ← 第 3 篇
└── ...
```

### 并行跑的纪律

1. **每个 T 一个新会话**（不是多篇塞一个会话）
2. **每篇独立文件**（不要混在一起）
3. **每篇独立的 _handoff/ YAML**
4. **session 间不要引用上下文**——只读文件

### 多篇优先级管理

```bash
# 看所有进行中的文章 + 当前阶段
for f in test_run/选题_*.md; do
  echo "=== $f ==="
  grep -A 5 "## 进度" "$f" | head -7
  echo
done
```

## 场景 4：完全丢失上下文（连 test_run/ 都没保存）

### 灾难恢复

如果连 `test_run/` 文件都没了，只能靠：

1. **飞书表格**（如果已发到草稿箱/已发布，标题和链接都在）
2. **Claude Code session log**（`~/.claude/projects/`）
3. **Slack/Telegram 历史对话**（如果之前讨论过选题）

### 预防措施

- **每个 T 完成后立刻 git commit**（哪怕只是 test_run/ 内部）
- **每天结束时跑一次 git push**（到 GitHub 私有仓库）
- **不要只在一个设备上跑**（云端有备份）

## 上下文快满的 3 个信号

### 信号 1：AI 开始重复自己

```
看到 AI 说类似的话：
- "根据上面的内容..."（超过 3 次）
- "继续上一个话题..."
- "如前所述..."
```

→ **应对**：立刻 `/new` 开新会话，按"5 分钟恢复"步骤继续

### 信号 2：AI 引用错的"前文"

```
AI 说：
- "你刚才说 13 升热水器..."（但你没说过）
- "按照之前选的角度 5..."（但你选的是角度 3）
```

→ **应对**：**立即停止**，开新会话。**这是上下文错乱的红线信号**

### 信号 3：AI 输出质量明显下降

```
- 标题不再符合 25-29 字规则
- 骨架五步漏掉一步
- AI 味词重新出现
- 自检时不再引用 assets/
```

→ **应对**：开新会话 + 把当前最好的部分拷到 test_run/ 备份

## 应急命令清单

```bash
# 看当前在跑的进度
ls -lt test_run/选题_*.md | head -3

# 看 _handoff/ 最近的 YAML
ls -lt test_run/_handoff/*.yaml | head -3

# 看 git 最近提交
git log --oneline -5

# 看某篇的当前进度
grep "## 进度" -A 10 test_run/选题_2026-06-11_冰箱_法式门vs对开门.md
```

## 写在最后

**上下文管理的本质是"让文件当记忆，让对话当临时计算区"**。

对话只做一件事：读文件 → 处理 → 写文件。

不要让对话记得太多——它不该是"数据库"，只该是"处理器"。
