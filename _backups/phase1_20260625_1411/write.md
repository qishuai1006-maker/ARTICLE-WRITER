# /write · 单篇生产 Loop

**输入参数**：$ARGUMENTS

## 解析输入
从 $ARGUMENTS 识别两样：
- **对标爆款**：文章全文 / 链接 / 截图描述
- **目标品类**：空调/冰箱/电视/洗衣机/油烟机/热水器/洗碗机等

若任一缺失，**别让 CEO 填空**——按 memory `ceo-triggers-i-pitch-topics`，我主动出选题方案表（Step 0.5）给 CEO 点头/微调，CEO 只说"开工/今天写"也能跑。仅在推品手册/MCP 查不到的型号参数时停问 CEO（不准瞎编）。

---

## 适用范围与账号
本命令由 Claude Code 执行，**只生产公司双号（牛科技 / 牛科技说）**。个人号（宅研社 / 北北ks）不归本流程，交给其他智能体。

## 决策原则（贯穿全程 · CEO 授权自主决策）
以"今日头条爆款创作者"的判断标准做每一个内容决策——**不选自己觉得高级/完整/好看的，选信息流里用户最可能停下来的**：
- **选题**：购买焦虑 / 避坑需求 / 决策痛感
- **标题**：点击理由够强（冲突 + 损失感 + 明确承诺）
- **封面**：缩略图下主体清楚、矛盾一眼可见
- **开头**：前三句快速点痛点 / 破误区 / 给继续读的理由
- **正文**：按用户决策路径推进，不堆知识
- **表达**：参数翻译成生活后果
- **观点**：明确但有边界

总原则：**先让用户停下来 → 再让用户信你 → 最后让用户知道怎么选。**

不再抛多选项让 CEO 选；CEO 只审最终成稿。仅在下列**红线**触发时停下问 CEO：
1. 推品手册 / 知识库 / MCP 查不到的型号参数（不准编造）
2. A 类合规禁词且无白名单替代
3. 选题撞车撞死 / 信息增益填不出 / 证据对象与近 14 天重复

## 执行流程（自动推进 · 仅红线处停）

### Step 0 · 组建 Agent team + 防卡死铁律（多片并行 / 长流程必读）
每篇开工优先派子 agent 跑全流程（主控只调度/校验/验收，严禁单上下文从头干到尾——会爆+不可持续）。**派单 prompt 必带以下 4 条防卡死铁律**（2026-06-21 两个子 agent 各卡死 50 分钟、主控慌乱连派 4 次的实测教训）：

1. **数据调研只用已预加载的 MCP**：`mcp__web-search-prime__web_search_prime` + `mcp__web_reader__webReader`。**严禁 WebSearch / WebFetch**——它们是 deferred 工具，子 agent 独立上下文不先 ToolSearch 加载直接调必报错卡死。
2. **Chrome 渲染 30 秒超时跳过**：`Scripts/render_html_to_png.py` 调用后 30 秒无返回立即判卡死，信息图改 Pillow 草稿 / Markdown 表格占位，**绝不卡在 Chrome**。
3. **每步立即落盘**：完成 01 / 01c / 02 / 02b / 03 / 04 立即写文件，别在内存憋大招——主控靠文件 mtime 判活。
4. **最小必读**：只读当前环节必需文件，不一次读 SOP+CLAUDE+4 Agent+全套 Skills 爆上下文。

**判死与处置（主控执行）**：
- 子 agent 静默 ≥15 分钟无落盘 → SendMessage 探活 1 次
- 30 秒内无回应 → **判死，主控立即接管该篇续做**（读已落盘产物接着跑，不从头重跑，不再干等）
- 接管后用 Write / Bash heredoc 直接落盘，**不再派同名子 agent**（昨天派 4 次越派越乱）

### Step 0.5 · 选题方案表（开工必出 · CEO 点头才进 Step 1 · 全程唯一确认点）

**背景**：CEO 只说"开工/今天写"，不定品类母体细节——`/write` $ARGUMENTS 经常缺品类/对标。memory `ceo-triggers-i-pitch-topics`：**我主动出选题方案表，CEO 点头或微调，别让 CEO 填品类母体空**。原约定只活在 memory 里（叙述性），没落成可检查产物 → 历史版本直接进 Step 1 拆解，跳过"我出方案→CEO 点头"。本步把它钉进流程层（呼应 [[narrative-must-have-checkable-artifact]]），选题是第一闸，比成稿更值得确认。

**触发**：每次 `/write` 开工必出（即使 CEO 给了品类，母体/评论发动机/标题方向仍需定）。CEO 已直接下发完整对标文章+品类 → 可跳过本步直接 Step 1。

**动作**（主控亲跑，不派子 agent——选题判断是质量第一闸）：
1. 按 `Skills/08-选题方案表模板.md` 出选题方案表：
   - **5 角度撒网**：覆盖 ≥2 母体（`运营方法论/02_爆款公式库.md` + `04_爆文内核库.md`）× ≥2 评论发动机（阵营争议 / 自查求助）；每角度给标题草案（25-29 字）+ 字数 + 撞车风险 + 弹药充足度。撒网本身即信息增益判断——5 个角度都填不出独家判断 = 这个品类弹药不足，先补库（`运营方法论/05_家电参数翻译库.md` 本品类 ≥3 条）再撒。
   - **撞车预检**：每个候选角度跑 `python3 Scripts/check_topic_collision.py [账号] [品类] [关键词] --title "[候选标题]"`，同核心对立已做过且上次展现 >1 万 → 标红淘汰或强制换锐角。
   - **选定 1 个**：给 **≥3 条数据支撑理由**（公式生命周期 🟢🟡🔴 / 撞车空白 / 弹药充足度 L3 / 账号适配 / 评论发动机强度 / 信息增益可填性，任选 ≥3）+ 风险点（风险必须给缓解动作，落到 Step 2 or 2.5）。
   - **核心抓手 ≥3**：给 Step 2 拆解 + Step 2.5 调研的明确查询方向（不是空方向）。
2. **落盘**：`outputs/[账号]_[品类]_[日期]/00_选题方案表.md`（编号 00，项目目录最早产物；Step 7.5 状态卡 + `/fupan` 复盘可追溯选题决策）。
3. **交 CEO 点头**：输出方案表 + 第五节"给 CEO 的决定项"（账号 / 品类 / 标题方向 / 母体 / 评论发动机，附我推荐 + 备选）。CEO 微调 → 更新落盘；CEO "继续/开" → 进 Step 1。

**闸门**：**CEO 未点头不进 Step 1**（选题错了 Step 1-9 全部白干，是全程自动流里除红线外唯一的 CEO 确认点）。CEO 已直接给对标+品类跳过本步的，也要在状态卡"选题决策依据"字段记一句"CEO 直接下发对标，跳过选题方案表"。

### Step 1 · 召回（动笔前必做 · 提命中率）
这是 designing loops 的核心——带全套上下文动笔，不是空 prompt。依次读取内化：
1. `对标拆解库/品类弹药包/[品类].md` — TOP爆款钩子 / 限流反面 / 最强结构 / 未消费机会
2. `运营方法论/02_爆款公式库.md` — 选公式（看生命周期，优先🟢活跃）
3. `运营方法论/03_头条爆文认知清单.md` — 标题三法则 / 反直觉规律 / 禁词不钝化 / 否定句扑街
4. `运营方法论/01_对标拆解工作流规范.md` — 拆解心法 + 迁移6问
5. **飞轮合环（强制）**：跑 `python3 Scripts/loop_status.py`——若公司号有待复盘超期，**先提示 CEO 跑 /fupan 再生产**（不开盲区新稿）；读 `projects/` 下公司号最近 `06_归档复盘卡`（若存在）的"下次动作/可复用点/问题点"，本篇必须回应（见 Step 3 第 6 项）。

若弹药包不存在或数据过旧，先跑 `python3 Scripts/gen_category_ammo.py` 刷新再继续。

### Step 2 · 01 情报拆解（自动）
按拆解心法解剖对标：钩子层（点击驱动力）/ 情绪骨架（破冰→反常识→痛点放大→决策降维）/ 品类乾坤大挪移（保留需求机制，替换品类证据）。过原创迁移6问。产出拆解卡，**不写正文**。

### Step 2.5 · 01c 数据调研（动笔前必做 · 堵"反推手册瞎编"）

**背景**：SOP §② 早已定义 01c（5 必查项 + 断点 §九），但本命令历史版本跳过了它——0621 牛科技空调篇子 agent 没做 01c，直接拿推品手册反推型号价格，导致 02 编造数字（"贵 239 元"无来源）、03 删 UNSURE 后标题主线空洞化（lint 照样 PASS）。本步把 01c 钉进流程层，让标题/正文里每个数字 born-verified，不是反推出来的。

**主控亲跑**（不派子 agent）：调研是质量地基，0621 实测子 agent 跳过 01c 反推手册编数字。01c 必须主控用 MCP 亲跑，全程留痕；子 agent 可跑 01/02/03/04，但 01c 留在主控。

**数据源（只用已预加载的 MCP · 实测 2026-06-22 通）**：
- `mcp__web-search-prime__web_search_prime`：搜 "[型号] 价格/销量/差评"、"[品类] 选购 爆款"、"[型号] vs [竞品]"
- `mcp__web_reader__webReader`：抓京东商品页 / 什么值得买 / 知乎评测 / 头条爆款正文（search 给不全时补结构化数据）
- ⚠️ **严禁 `WebSearch`/`WebFetch`**——deferred 工具，子 agent 独立上下文不先 ToolSearch 加载直接调必报错卡死，见 Step 0 铁律 #1。
- **手动兜底**：后台销量 / 付费研报 / Gemini 深度追问这类 MCP 拿不到的，标缺项或请 CEO 手动跑后贴回，**不准假装查到**。

**动作**：
1. 跑 **≥2 条外部查询**，覆盖 SOP §② 5 必查项（销量梯队 / 价格区间 / 用户痛点评论 / 竞品爆款 / 热度信号）；查不到的标缺项 + 是否影响信息增益。
2. **标题数字预验（堵空洞化源头）**：若拆解卡/初步标题方向含具体数字（价格/差价/参数），01c 必须在外部源核实该数字真实存在（京东活动价/国补后价/评测对比价）。查不到 → **回 Step 2 调标题方向，不准带未验证数字进 Step 3**。验证过的数字标公开来源（京东/什么值得买/知乎评测等），进 02b 证据卡时不再是 UNSURE。
3. **按 L3 模板填弹药包**：用 `家电知识库/_templates/L3_调研报告_模板.md` 跑全 11 节（选题判断 / 观点候选 ≥3 / 痛点清单 ≥8 / 参数翻译表 / 型号价格对比表 / 信息增益 ≥5 / 评论钩子 / 标题方向 5-8 个 / 封面建议 / 事实风险 / 写前闸门自检）。模板里的 8 项写前闸门自检全填，缺口的在"最终结论"行写明。

**落盘（主产物落 L3 · CEO 0622 定）**：`家电知识库/L3_场景调研报告/YYYYMMDD_牛科技或牛科技说_品类_选题关键词_L3调研报告.md`（命名带牛科技/牛科技说账号，跟其他智能体的宅研社/北北ks 区分）。`outputs/[账号]_[品类]_[日期]/` 不再堆 01c 临时文件；Step 7.5 组装状态卡时"必召回 L3 场景调研"字段填这个 L3 路径。

**闸门（双闸 · 不过不进 Step 3）**：
- **数据采集闸**：5 项必查跑过（缺项标明 + 影响判断）+ 标题数字（若有）已外部验证。
- **弹药包闸**：L3 模板第 11 节 8 项写前闸门自检全"是"（3 可信来源 / 5 信息增益 / 参数翻译表 / 型号价格证据 / 痛点场景 / 明确观点非中庸 / 评论钩子 / 事实风险），缺口回 ②① 调选题或补查。
- 呼应 SOP §九断点"② 01c 数据调研落盘？"——本步落 L3 路径即落盘。

### Step 3 · 骨架定案（自动 · 不停 · 单方案决策）
基于拆解卡 + **Step 2.5 的 01c 已验证数据** + 弹药包 + 公式库，**自主定唯一骨架方案**（不写正文），6 项决策各附一句理由（供 /fupan 复盘重建"当时预判"）：
1. **公式/结构**：选定 1 个（附弹药包依据）
2. **标题**：定 1 个（25-29字，前 15 字钩子测试 + 冲突/损失/承诺；**标题里的每个数字必须来自 Step 2.5 的 01c 已验证数据**——价格/差价/参数不准凭推品手册反推，否则 Step 4.5 标题兑现检查 + hook 会拦）
3. **人设/账号**：牛科技 / 牛科技说 定 1 个（按双号策略的结构适配数据，见下注）
4. **文章骨架**：开场模式 / 段落推进 / 收尾模式 / 2 个信息图位
5. **核心论点 + 独家增量**：这篇比对标多出什么（迁移闸门第 5 问）
6. **近期教训回应**：引用 Step 1 读到的最近公司号复盘卡 ≥1 条教训（下次动作/可复用点/问题点），写明本篇怎么用/怎么避；无复盘卡时填"暂无近期复盘"，但 loop_status 显示有待复盘超期则先停。

落盘 `01b_骨架定案_[品类].md`，**不停**，直接进 Step 4。
> 账号选择注：`运营方法论/01_账号定位与双号策略.md` 基于 64 篇数据建议 牛科技走 S1/S4/S6/A1/A4（工具型）、牛科技说走 S2/S3/S5（人设型，CTR +35%）。CEO 现述"两号本质一样"，**在该冲突未最终确认前，默认沿用此数据-backed 适配**；待 CEO 定夺是否作废区分。

### Step 4 · 02 主笔正文（自动）
按定案骨架写完整初稿：
- 套 `Skills/05-牛科技长文原型规范.md`（6 骨架 / 8 开场 / 6 收尾，强制轮换）
- 去 AI 味 `Skills/04-活人写手感规范.md`（7 大白名单法则）
- 节奏 `Skills/07-节奏与情绪引擎.md`（W 型情绪波形 / 段落长短交替）
- 标题 25-29 字；第一段 ≤50 字直击痛点
- 预留 2 处 `[此处插入信息图X：...]`
- 同步产出 `轻量证据卡`（型号/参数/价格/售后登记；UNSURE 不得进正文，SINGLE_SOURCE 加边界）
- 附合规自检清单

### Step 4.5 · 主控对账（02→03 之间 · 堵"标题承诺空洞化"）
**背景**：02 主笔/子 agent 可能在"删 UNSURE 推论数字"后留下标题兑现不了的空洞——标题说"贵 239 元"，正文却把 239 和对比数据都删了。lint 照样 PASS（lint 只数正文有什么，不查标题要什么），昨天牛科技空调就栽在这。这一步专堵这个洞，**是主控自检，不是 CEO 确认点**——CEO 授权全自动的大方向不变。

两件事都做完才进 Step 5：
1. **脚本硬查（双向闸门 · 2026-06-22 升级）**：
   ```
   python3 Scripts/check_title_delivery.py 02_首席主笔初稿_[品类].md --evidence 02b_轻量证据卡_[品类].md
   ```
   - **ERROR（正向·防夸张）**：`digit_missing` / `compare_pledge_broken` / `unsure_leak` / `hard_grey_word` → 不进 Step 5
     - 数字/对比/UNSURE 漏：回 01c 补真实数据让正文兑现，或换标题主线。**不准用"把强标题改成弱标题（删数字/型号）"逃避兑现**——那是闸门 B 点击钩子失守，且会被 P2 状态卡 lint 拦
     - `hard_grey_word`（买了必后悔/全家遭殃/闭眼入等纯恐吓强迫）：无信息能锚定，**直接换标题**，用 `Skills/06` §6.2 三种替代技术（信息权威感/真实悬念/精准场景代入）重写，不是词表替换
   - **WARN（反向·防平庸 + 软白名单）→ 主控语义复核定夺**：
     - `title_over_weak`（标题无冲击力元素 + 正文有 ≥3 硬实体）：判断文章类型——**工具型（清单/科普）标题弱属正常放过；钩子型（型号解码/价格段/阵营对决）标题该用上弹药**，参考 §6.2 三种替代技术把真实信息做成有效吸引（不是回到夸张）
     - `strength_word_needs_fulfillment`（竟/居然/真相是等）：本身不禁，按 §6.1 三个核心检验复核正文兑现了没有
2. **主控语义复核**（脚本做不了，主控必做 · 双向）：
   - **正向**：02b 证据卡 UNSURE 项删完后，**标题承诺的主线是否还成立**？例：标题"X 贵 239 元"，正文必须有 X 和被对比方的具体配置——删了 UNSURE 又不补真实数据 = 主线空洞化 = 回 01c 或换主线，不准带着空洞进 03。
   - **反向**：标题是否**过度弱化**（兑现了但冲击力元素删光 = 平庸 = 爆款能力被阉割）？钩子型文章标题必须有数字/型号/对比/强度词至少其一锚定真实信息。
   - **三问校验**（挂创作时间轴，见 `Skills/06` §6.3）：创作前（吸引力来源是真实信息还是情绪操控？）→ 发布前（标题承诺正文兑现吗？）→ 发布后（`/fupan` 飞轮用数据定义边界）。

### Step 5 · 03 风控（自动）
- 100 分爆款预判：`Skills/02-出稿爆款质检规则.md`（6 维打分 + 校准）
- 词库扫描：`Skills/06-合规红线词库.md`（🔴A/🟧B/🟨C/⬜D 类逐项扣分）
- 事实核对：正文 vs 轻量证据卡逐条比对
- 写出 `03_风控主编终稿_[品类].md`（写入会自动触发 lint hook）
