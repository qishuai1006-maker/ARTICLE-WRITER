# T4 发布前自检清单

> **目标**：正文完成后，对照清单逐项检查，全部通过才能发布。

## 一、骨架完整性（12 项必查）

### 问题链（用此骨架时）

- [ ] 第一段是"痛点现场"（具体场景/数据）
- [ ] 第二段是"常见误区"（列 3 个坑）
- [ ] 第三段是"真正的原因"（挖到默认假设之下）
- [ ] 第四段是"解决方案"（具体操作序列）
- [ ] 第五段是"一句话带走"（金句 + 可截图可转发）
- [ ] 五步字数递进合理（不是头重脚轻）

### 故事线（用此骨架时）

- [ ] 第一段是"具体的时刻"（时间/地点/发生了什么/感受）
- [ ] 第二段是"当时的反应"（怎么想/做了什么决定/为什么）
- [ ] 第三段是"后来的转折"（什么改变了看法）
- [ ] 第四段是"现在的理解"（回头看怎么看）
- [ ] 第五段是"读者能带走的东西"（给正在经历的人一句话）
- [ ] 故事弧线连贯（不是平铺直叙）

### 拆解面（用此骨架时）

- [ ] 第一段是"主流观点"（客观陈述，不讽刺）
- [ ] 第二段是"数据的裂缝"（具体数据/案例与主流矛盾）
- [ ] 第三段是"被忽略的变量"（解释矛盾为什么存在）
- [ ] 第四段是"新的视角"（基于变量重新理解）
- [ ] 第五段是"对读者的意义"（今天开始可以做什么不同）
- [ ] "推翻常识"逻辑自洽（不是抬杠）

## 二、三段一致性

| 检查项 | 标准 | 不通过怎么改 |
| --- | --- | --- |
| **读者决策点** | 第二/第三步是不是"卧槽"那一刻 | 加具体场景/数据/反常识 |
| **痛点 → 方案** | 读者到第四步是否知道"下一步做什么" | 把"应该 / 建议"换成"第一步 X、第二步 Y" |
| **标题 → 开头** | 标题承诺的，开头 100 字内是否兑现 | 标题党 vs 正文脱节 |

## 三、AI 味自检（核心禁词）

### ERROR 级（必须改）

| 词 | 替换 |
| --- | --- |
| 综上所述 | 删 |
| 不可否认 | 删 |
| 让我们来看看 | 删 |
| 接下来让我们 | 删 |
| 值得注意的是 | 删 |
| 毋庸置疑 | 删 |
| 毫无疑问 | 删 |
| 不得不说 | 删 |
| 这意味着 | 删 |
| 不难发现 | 删 |
| 本质上 | 删 |
| 换句话说 | 删 |

### WARNING 级（建议改）

| 词 | 替换建议 |
| --- | --- |
| 必须 / 一定要 | 建议 |
| 最好的 / 最强的 | 表现突出的 |
| 唯一 / 独家 | 少有的 |
| 第一 | 领先 |
| 顶级 | 高端 |
| 碾压 / 吊打 | 明显领先 |
| 没有对手 | 属于第一梯队 |

**自动化工具**：跑 `python3 Scripts/lint_article.py outputs/你的文章.md --json` 一键扫描

## 四、绝对化用语合规

参考 `Skills/04-合规与质量双审Skill.md` 中的合规检查清单：

- [ ] 无"国家级 / 最高级 / 最佳"等广告法违禁词
- [ ] 无未经验证的产品参数声明
- [ ] 无"独家 / 唯一"等夸大表述
- [ ] 数据来源可追溯（正文标注与 T2 验证表一致）

## 五、评论钩子检查

- [ ] 结尾有显式评论引导（不是纯金句结束）
- [ ] 评论钩子足够具体（不是"你怎么看"这种废话）
- [ ] 钩子能引发不同意见（"评论区聊聊"vs"你觉得对吗"差异巨大）

## 六、配图检查（极简规则）

- [ ] 总图片数 1-2 张（不许堆图）
- [ ] 第一张是主图（标题承诺的视觉化）
- [ ] 图片分辨率 ≥1080P
- [ ] 图片有信息量（不是装饰）

## 七、字数检查

- [ ] 正文 1500-2500 字（头条最优区间）
- [ ] 开头 ≤200 字（钩子要早）
- [ ] 结尾 ≤300 字（评论钩子要短促有力）

## 自检脚本

```bash
# 一键自动化检查（v7.2 沿用）
python3 Scripts/lint_article.py outputs/你的文章.md --json

# 结构验证
python3 Scripts/validate_outputs.py --verbose
```
